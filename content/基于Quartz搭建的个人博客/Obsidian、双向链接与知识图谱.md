## 一、一句话理解

Obsidian 是管理 Markdown 笔记的工具；双向链接负责连接笔记；知识图谱负责把这些连接画出来。

## 二、理论：它是什么

### 2.1 Obsidian 是什么

Obsidian 可以理解成一个个人知识库工具。

它的笔记本质上是保存在电脑上的 `.md` 文件，Obsidian 负责帮助我们编写、搜索、连接和查看这些笔记。

一个 Obsidian 知识库通常叫作 Vault，也就是一个文件夹。文件夹中的 `.obsidian` 目录保存了这个知识库的设置、插件和主题配置。

### 2.2 双向链接是什么

在 Obsidian 中，可以使用下面的格式链接到另一篇笔记：

```markdown
我正在学习 [[面向对象]]。
```

`[[面向对象]]` 表示链接到名为“面向对象”的笔记。点击链接即可打开对应笔记。

### 2.3 知识图谱是什么

知识图谱可以理解成“笔记关系地图”。

- 一个圆点代表一篇笔记。
- 一条线代表两篇笔记之间存在链接。
- 被很多笔记链接的笔记，通常会有更多连接。

## 三、理论：它是怎么工作的

### 3.1 双向链接的工作方式

假设有两篇笔记：

```text
Java基础.md
面向对象.md
```

在 `Java基础.md` 中写入：

```markdown
我正在学习 [[面向对象]]。
```

这会产生两个效果：

1. 从“Java基础”可以点击链接打开“面向对象”。
2. 打开“面向对象”时，可以在反向链接区域看到“Java基础”。

严格来说，文件中保存的是从 A 指向 B 的链接；Obsidian 根据链接关系生成反向链接，所以使用体验像是双向的。如果在两篇笔记中都主动写入对方链接，才是两边都保存了明确链接。

### 3.2 知识图谱的组成

知识图谱主要由两部分组成：

- 节点：笔记、文件或概念。
- 边：笔记之间的链接关系。

例如：

```text
Java基础 ─── 面向对象 ─── 继承
                         │
                       多态
```

这张关系图表示“Java基础”和“面向对象”有关，“面向对象”和“继承”有关，“继承”和“多态”有关。

## 四、实践：可以拿来干什么

Obsidian 和这些链接功能可以用于：

- 整理编程、英语、历史等学习笔记。
- 记录工作经验和项目资料。
- 管理读书笔记。
- 关联业务概念、技术方案和问题记录。
- 通过反向链接找出某个概念被哪些内容引用。
- 通过知识图谱观察知识之间的整体关系。

传统文件夹更像把内容放进不同抽屉；笔记链接则像给内容建立了可追踪的关系。

## 五、最小例子

创建三篇笔记。

### 5.1 Java基础

```markdown
# Java基础

Java 是一门面向对象的编程语言。

相关概念：[[面向对象]]
```

### 5.2 面向对象

```markdown
# 面向对象

面向对象包含：

- [[封装]]
- [[继承]]
- [[多态]]
```

### 5.3 继承

```markdown
# 继承

继承是面向对象的重要特征之一。
```

这样就建立了一条知识关系：

```text
Java基础 → 面向对象 → 继承
```

打开“面向对象”笔记时，还能看到“Java基础”通过反向链接引用了它。

## 六、边界与常见误区

### 6.1 知识图谱不会自动生成知识

如果笔记之间没有建立链接，图谱就无法展示有意义的关系。

### 6.2 链接越多不一定越好

链接应该表达真实关系，例如“属于”“解释”“对比”“依赖”或“应用于”。随意添加链接会让图谱变得混乱。

### 6.3 不必一开始就设计复杂体系

刚开始只需要做到：一件事情写一篇笔记，遇到相关概念就使用 `[[笔记名]]`，之后通过反向链接回顾关系。

### 6.4 双向链接不等于自动理解

Obsidian 能发现笔记之间的链接，但不会自动判断两篇笔记在业务或知识上的真实含义。关系仍然需要由我们建立和维护。

## 七、其他好用功能

### 7.1 属性：给笔记增加结构化信息

属性是写在笔记顶部的元数据，适合记录标题、日期、状态、标签、数字或是否完成等信息。

```yaml
---
type: 学习笔记
status: 进行中
date: 2026-08-18
tags:
  - Obsidian
  - 知识管理
---
```

属性的作用是让笔记不只有正文，还拥有可以被筛选和整理的字段。

### 7.2 Bases：把笔记当成数据库查看

Bases 是 Obsidian 的核心插件，可以根据笔记属性生成类似数据库的表格、列表或卡片视图，并支持筛选、排序和分组。

例如，可以给读书笔记增加 `作者`、`评分`、`阅读状态` 属性，然后用 Bases 做出“正在阅读”“已读完”的书籍列表。

### 7.3 嵌入：在一篇笔记里显示另一篇笔记

普通链接是跳转，嵌入则是把内容直接显示在当前笔记中：

```markdown
![[项目背景]]
```

也可以只嵌入另一篇笔记中的某个标题、段落、图片、PDF 或搜索结果。

适合用来制作项目首页、知识目录和汇总页面。源笔记更新后，嵌入内容也会同步变化。

### 7.4 Canvas：用画布整理复杂关系

Canvas 是一块可以自由摆放卡片的无限画布，可以把笔记、图片、PDF、网页和文字卡片放在一起，再用线连接它们。

它适合：

- 整理系统架构。
- 规划文章结构。
- 绘制业务流程。
- 做头脑风暴。
- 把零散笔记整理成整体思路。

### 7.5 每日笔记和模板：减少重复劳动

每日笔记可以自动创建当天的笔记，适合记录工作日志、学习记录和待办事项。

模板可以预先写好固定结构，例如：

```markdown
# {{date:YYYY-MM-DD}}

## 今日任务

- [ ]

## 学到的内容

## 遇到的问题
```

以后新建笔记时，直接插入模板即可，不需要每次重新写标题和小节。

### 7.6 搜索、命令面板和快捷键

命令面板可以搜索并执行 Obsidian 的各种功能；快速切换器可以快速打开或创建笔记；搜索功能可以查找全文、标签、属性和任务。

这类功能看起来简单，但笔记多起来之后，比手动翻文件夹高效很多。

### 7.7 Web Clipper：把网页内容保存进知识库

Web Clipper 是官方浏览器扩展，可以把网页正文、选中的内容或高亮内容保存到 Obsidian。它还支持模板，能够自动整理标题、网址、作者和标签等信息。

例如，看到一篇技术文章后，可以保存为：

```yaml
---
source: 网页地址
type: 技术文章
tags:
  - 待整理
---
```

### 7.8 插件、主题和同步

核心插件是 Obsidian 自带的功能，社区插件则由其他用户开发，可以扩展任务管理、日历、图表、自动化等能力。

主题和 CSS 片段可以改变外观；同步功能可以让多个设备使用同一份知识库；发布功能可以把笔记整理成网站、Wiki 或文档站。

插件越多不一定越好。建议先使用核心功能，只有遇到明确需求时再安装插件，并定期清理长期不用的插件。

## 八、推荐学习顺序

建议按下面的顺序学习：

1. `[[笔记名]]` 内部链接和反向链接。
2. 标签和属性。
3. 模板与每日笔记。
4. 嵌入和 Canvas。
5. Bases 数据库视图。
6. Web Clipper 和社区插件。

先把笔记写起来，再逐步增加工具功能，比一开始设计复杂体系更容易坚持。

## 九、总结

Obsidian 不只是写笔记，还可以把笔记变成一个可查询、可组合、可视化的个人知识库。

最值得先掌握的是：用链接建立关系，用属性描述笔记，用模板减少重复，用嵌入制作汇总页，再根据需要使用 Canvas、Bases、Web Clipper 和插件。
