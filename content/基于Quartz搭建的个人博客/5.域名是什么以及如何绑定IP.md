## 一、🪴 一句话理解

> [!tip] 核心结论
> **域名**是网站在互联网上的“地址”，**IP 地址**是服务器的“门牌号”，**DNS** 负责把域名翻译成 IP 地址，让用户输入域名后找到服务器上的 Quartz 博客。

## 二、🧭 理论：域名、IP 和服务器是什么

### 2.1 域名是什么

域名（Domain Name）是方便人记忆的网站地址，例如：

```text
example.com
blog.example.com
```

直接记 IP 地址比较困难，而且服务器更换 IP 后，所有人都需要记住新的地址。域名把这件事隔离开了：用户记住域名，DNS 负责找到当前服务器。

可以把它理解为：

| 名词 | 生活中的比喻 | 实际作用 |
| --- | --- | --- |
| 域名 | 店铺名称 | 方便用户记忆和访问 |
| IP 地址 | 店铺的具体地址 | 定位网络中的服务器 |
| DNS | 查地址的通讯录 | 把域名转换成 IP 地址 |
| 服务器 | 真正营业的店铺 | 保存并返回网站内容 |

### 2.2 IP 地址是什么

IP 地址是网络设备的数字地址。公网服务器通常会有一个可以从互联网访问的公网 IP，例如：

```text
47.99.178.186
```

上面的地址只是示例。配置自己的域名时，应填写服务器实际的公网 IP，不要直接照抄示例。

常见 IP 类型有：

| 类型 | 说明 |
| --- | --- |
| 公网 IP | 互联网用户可以访问的服务器地址 |
| 内网 IP | 只在局域网或云平台内部使用的地址 |
| IPv4 | 例如 47.99.178.186，目前最常见 |
| IPv6 | 新一代 IP 地址，格式通常更长 |

域名必须解析到用户能够访问的公网地址。把域名解析到内网 IP，公网用户通常无法访问。

### 2.3 服务器是什么

服务器是一台长期联网的计算机。对于当前 Quartz 博客来说，它主要负责：

1. 保存 Quartz 构建后生成的静态网页文件。
2. 接收浏览器请求，并把网页文件返回给访问者。

当前博客的基本关系是：

```text
Markdown 笔记
       ↓
   Quartz 构建
       ↓
生成 public 静态文件
       ↓
上传到服务器网站目录
       ↓
用户通过域名访问
```

## 三、⚙️ 理论：DNS 是怎么工作的

DNS 的全称是 Domain Name System（域名系统）。它的作用是把人容易记住的域名转换成计算机使用的 IP 地址。

用户访问：

```text
https://blog.example.com
```

浏览器大致经历以下过程：

```text
浏览器请求 blog.example.com
            ↓
查询 DNS 记录
            ↓
得到服务器公网 IP
            ↓
连接服务器
            ↓
服务器返回 Quartz 网页
```

DNS 解析记录中最常见的是：

| 记录类型 | 作用 | 常见用途 |
| --- | --- | --- |
| A | 把域名指向 IPv4 地址 | example.com → 47.99.178.186 |
| AAAA | 把域名指向 IPv6 地址 | 域名 → IPv6 地址 |
| CNAME | 把一个域名指向另一个域名 | www.example.com → example.com |
| TXT | 保存文本验证信息 | 域名所有权验证等 |
| MX | 指定邮件服务器 | 接收域名邮箱邮件 |

> [!tip] 最小配置
> 如果只是把一个域名绑定到一台 IPv4 服务器，通常只需要配置一条 **A 记录**。

### 3.1 根域名和子域名

假设购买的域名是：

```text
example.com
```

它可以拆成：

- 根域名：example.com
- 子域名：www.example.com
- 博客子域名：blog.example.com

常见设计有两种：

```text
example.com       → 博客首页
www.example.com   → 同一个博客
```

或者：

```text
example.com       → 其他用途
blog.example.com  → Quartz 博客
```

如果只是搭建个人博客，使用根域名或 blog 子域名都可以。关键是提前确定对外使用哪个地址，并让 Quartz 的 baseUrl 与最终访问地址保持一致。

### 3.2 DNS 生效不是立即完成的

DNS 记录通常带有 TTL（缓存时间）。修改记录后，不同地区、不同网络的 DNS 缓存更新时间可能不同，因此可能出现：

- 自己的电脑已经可以访问，别人的网络还不行。
- 根域名已经生效，www 子域名还没有生效。
- 浏览器仍然打开旧服务器。

这不一定代表配置错误。应先检查记录是否正确，再等待缓存逐步更新。

## 四、🛠️ 实践：从购买域名到绑定服务器

> [!info] 先看全流程
> 注册域名 → 获取服务器公网 IP → 添加 DNS 记录 → 配置网站目录 → 启用 HTTPS → 修改 Quartz 的 `baseUrl` → 重新构建并部署。

### 4.1 第一步：选择并注册域名

选择域名时，优先考虑：

- 简短，方便输入和口头告知。
- 拼写清楚，尽量避免连续多个连字符。
- 与博客内容或个人品牌有关。
- 确认自己拥有域名管理权限。
- 记录注册商账号、续费时间和域名到期时间。

域名注册商、价格、实名或备案要求会因地区、后缀和政策变化，购买前应以注册商当前页面和所在地要求为准。

如果目标是“便宜、可靠、适合个人博客”，可以优先考虑以下平台。下面的价格以 2026-08-19 官网页面为准，实际结算价格可能受促销、汇率、税费和域名是否属于溢价域名影响。

- **Cloudflare Registrar**：适合希望长期省钱的人。`.com` 按注册局成本价收费，不额外加价，并免费提供隐私保护和 DNSSEC。需要注意，使用 Cloudflare Registrar 注册的域名必须使用 Cloudflare DNS，不能改用其他 DNS 服务商。[官方说明](https://www.cloudflare.com/en-gb/application-services/products/registrar/buy-com-domains/)
- **Porkbun**：综合体验较好，`.com` 当前注册和续费约为 11.06 美元/年，价格透明，并提供免费隐私保护。[官方价格](https://porkbun.com/tld/features)
- **Spaceship**：当前 `.com` 首年约 8.88 美元，续费约 9.98 美元/年，并提供免费隐私保护，适合比较看重价格的人。[官方价格](https://www.spaceship.com/domains/)
- **阿里云万网**：如果服务器在中国大陆，并且准备办理 ICP 备案，阿里云在国内支付、客服和备案流程衔接方面更方便。但具体价格会随活动和域名后缀变化，应以购买页面实际价格为准。[阿里云域名价格](https://wanwang.aliyun.com/help/price)

对于个人 Quartz 博客，我的建议是：能接受 Cloudflare DNS 就优先考虑 Cloudflare Registrar；想保留 DNS 服务商选择自由，可以考虑 Porkbun 或 Spaceship；如果使用中国大陆服务器并准备备案，可以直接选阿里云万网。

不要只看首年价格，要重点比较续费价格。例如，Spaceship 的 `.xyz` 首年价格很低，但当前续费约为 12.52 美元/年。个人博客通常优先选择 `.com`；如果 `.com` 已被注册，再考虑其他后缀。

如果服务器在中国大陆，正式通过域名提供网站服务通常还需要办理备案。工信部规定，在中国境内提供非经营性互联网信息服务应履行备案手续。[工信部备案说明](https://www.miit.gov.cn/gyhxxhb/jgsj/cyzcyfgs/bmgz/xxtxl/art/2024/art_84a0cfa0ebd049bbbe751dca9a008e56.html)

### 4.2 第二步：确认服务器公网 IP

在服务器管理面板中找到公网 IPv4 地址，记为：

```text
你的服务器公网 IPv4：<SERVER_IP>
```

不要把以下地址当作公网 IP：

```text
127.0.0.1
localhost
192.168.x.x
10.x.x.x
172.16.x.x 到 172.31.x.x
```

这些通常是本机回环地址或内网地址，互联网用户无法通过它们访问你的服务器。

> [!warning] 关键判断
> 能在服务器本机访问，不代表互联网用户能访问。域名解析必须指向用户可以到达的公网 IP。

### 4.3 第三步：添加 A 记录

在域名注册商的 DNS 管理页面中新增 A 记录。

假设：

- 域名是 example.com。
- 服务器公网 IPv4 是 <SERVER_IP>。
- 根域名直接作为博客地址。

可以配置：

| 主机记录 | 记录类型 | 记录值 |
| --- | --- | --- |
| @ | A | <SERVER_IP> |

这里的 @ 通常表示根域名 example.com。不同注册商的字段名称可能不同，但含义基本一致。

如果还想让 www.example.com 访问同一个博客，可以增加：

| 主机记录 | 记录类型 | 记录值 |
| --- | --- | --- |
| www | CNAME | example.com |

> [!tip] 推荐的最小 DNS 配置
> 先配置 `@ → A → <SERVER_IP>`，确认根域名可以访问后，再按需要增加 `www → CNAME → example.com`。

### 4.4 第四步：验证 DNS 解析

在本机终端执行：

```bash
dig +short example.com
```

如果使用 www 子域名，再检查：

```bash
dig +short www.example.com
```

期望结果是看到服务器实际公网 IP：

```text
<SERVER_IP>
```

也可以使用：

```bash
nslookup example.com
```

如果结果为空或还是旧 IP，先检查记录名称、记录类型和记录值，再考虑 DNS 缓存尚未更新。

> [!info] 验证通过的标志
> `dig +short example.com` 能返回服务器实际公网 IP，说明 DNS 这一层已经基本打通；这还不代表网站绑定和 HTTPS 已经完成。

### 4.5 在服务器上配置网站域名

DNS 只负责“找到服务器”，服务器还需要知道这个域名应该交给哪一个网站目录处理。

以当前 Quartz 博客为例，服务器需要将域名绑定到存放构建结果的目录：

```text
/www/AfykeBlog/afyke-blog
```

如果使用宝塔、Nginx 或 Caddy 等工具，需要在网站配置中填写：

- 网站域名：example.com
- 可选域名：www.example.com
- 网站根目录：/www/AfykeBlog/afyke-blog

核心关系是：

```text
域名 → 服务器公网 IP → 网站配置 → Quartz 静态文件目录
```

### 4.6 配置 HTTPS

HTTPS 是加密后的 HTTP。配置完成后，用户通过下面的地址访问：

```text
https://example.com
```

服务器通常需要为域名申请 TLS 证书。证书申请前，域名一般需要已经解析到正确的服务器，并且服务器能够接收相关验证请求。

配置 HTTPS 后应检查：

- http://example.com 是否能跳转到 HTTPS。
- 浏览器地址栏是否显示安全连接。
- 页面中的图片、脚本和样式是否仍然使用 HTTP 地址。
- www 和根域名是否按照预期跳转或统一。

不要把“DNS 已经解析成功”误认为“HTTPS 已经配置完成”。DNS、网站绑定和证书是三个不同步骤。

### 4.7 修改 Quartz 的 baseUrl

Quartz 需要知道博客最终对外使用的域名。应在 Quartz 配置文件中将 baseUrl 设置为实际域名，例如：

```yaml
baseUrl: example.com
```

通常不要在 baseUrl 末尾增加 /，也不要把完整的 https:// 重复写入，具体格式以当前 Quartz 配置文件和版本说明为准。

修改后重新构建博客：

```bash
npx quartz build
```

然后按照现有部署方式，把新的 public 目录同步到服务器：

```text
Markdown 笔记
    ↓
Quartz build
    ↓
生成 public
    ↓
rsync 或 GitHub Actions 部署
    ↓
通过域名访问博客
```

## 五、🧪 最小例子：把 example.com 指向 Quartz 博客

假设当前条件如下：

```text
域名：example.com
服务器公网 IPv4：<SERVER_IP>
服务器网站目录：/www/AfykeBlog/afyke-blog
博客访问地址：https://example.com
```

### 5.1 DNS 配置

添加：

```text
主机记录：@
记录类型：A
记录值：<SERVER_IP>
```

可选地添加：

```text
主机记录：www
记录类型：CNAME
记录值：example.com
```

### 5.2 服务器网站配置

将网站域名配置为：

```text
example.com
www.example.com
```

将网站根目录配置为：

```text
/www/AfykeBlog/afyke-blog
```

然后申请并启用 HTTPS 证书。

### 5.3 Quartz 配置

将 baseUrl 设置为：

```yaml
baseUrl: example.com
```

重新构建并部署：

```bash
npx quartz build
```

最后验证：

```bash
dig +short example.com
curl -I https://example.com
```

如果 dig 返回正确 IP，curl 返回正常的 HTTP 响应，并且浏览器可以打开博客，说明从域名到 Quartz 网站的链路基本打通。

## 六、⚠️ 边界与常见误区

> [!warning] 先分清三件事
> **DNS 解析成功**只说明域名找到了服务器；**网站绑定成功**才说明服务器知道把请求交给哪个目录；**HTTPS 配置成功**才说明浏览器可以安全访问。三者需要分别检查。

购买域名不会自动得到服务器。域名只是地址，仍然需要服务器或静态托管平台保存并提供网站文件。

DNS 只能把域名指向 IP。服务器还需要配置网站域名、网站根目录和 Web 服务，否则即使解析正确，也可能看到默认页面或连接失败。

A 记录的值应该是 IP 地址：

```text
正确：47.99.178.186
错误：https://example.com
错误：example.com
```

如果要把一个域名指向另一个域名，应考虑 CNAME，而不是把域名文本填进 A 记录。

网站通常至少需要允许外部访问 HTTP 和 HTTPS 端口。若 DNS 正确但浏览器仍然连接超时，应检查：

- 云服务器安全组。
- 服务器防火墙。
- Nginx、Caddy 或宝塔网站是否正常运行。
- HTTP/HTTPS 端口是否监听。

如果服务器公网 IP 会变化，域名会再次指向旧地址。生产环境应使用稳定的公网 IP，或配置可靠的动态 DNS 方案。

解析成功只说明“域名找到了服务器”，不代表 HTTPS 证书已经正确。证书失效、域名不匹配或混合内容都可能导致浏览器警告。

example.com 与 www.example.com 是两个不同的域名。需要分别配置 DNS 和网站绑定，并决定一个主地址，另一个跳转过去。

## 七、✅ 总结

弄一个域名并绑定 Quartz 博客，本质上是完成四层连接：

```text
域名
  ↓ DNS 解析
公网 IP
  ↓ 网站配置
服务器网站目录
  ↓ 部署 public
Quartz 博客
```

最小记忆方法：

1. 注册一个域名。
2. 用 A 记录把域名指向服务器公网 IP。
3. 在服务器上把域名绑定到 Quartz 的网站目录。
4. 配置 HTTPS。
5. 将 Quartz 的 baseUrl 改成域名，重新构建并部署。

> [!tip] 一句话总结
> **域名负责让人找到网站，DNS 负责指路，服务器负责提供网页，Quartz 负责生成网页。**
