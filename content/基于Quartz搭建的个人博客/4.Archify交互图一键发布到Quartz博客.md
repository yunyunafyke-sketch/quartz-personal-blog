# Archify交互图一键发布到Quartz博客

## 1. 目标

使用 Archify 生成交互式 HTML 图后，将文件放入 Quartz 内容目录，经过 Quartz 构建和部署后：

- 本地 Quartz 可以打开交互图；
- 发布到服务器后可以直接在浏览器中打开；
- 新增交互图时不需要重复修改 Nginx；
- 通过现有的构建和部署流程一键发布。

## 2. Archify 文件保存位置

Archify 生成的 HTML 文件统一保存到：

```text
/Users/chenweili/Documents/quartz/content/archify/
```

以后使用 Archify 生成交互图时，默认直接将最终 HTML 输出到这个目录，不再保存到当前工作目录或临时目录；只有明确指定其他输出位置时才例外。

例如：

```text
content/archify/aop-unified-log-chain.html
content/archify/order-flow.html
content/archify/login-sequence.html
```

文件名使用英文和短横线，避免中文、空格和特殊字符影响服务器访问。

## 3. Quartz 构建后的文件形态

Quartz 构建后，Markdown 页面通常会生成带 `.html` 后缀的页面，例如：

```text
public/aboss-sso/技术说明/aop统一日志打印链路.html
```

但是，`content/archify/` 下的 HTML 文件会被 Quartz 的资源处理逻辑输出为无后缀文件：

```text
public/archify/aop-unified-log-chain
```

这不是文件丢失，也不要手动重命名。下一次构建时，手动改名会被覆盖。

本地 Quartz 开发服务器可以正确识别这个无后缀文件，但生产环境的浏览器可能将其当成下载文件。因此生产环境需要用 Nginx 提供一个统一的 `.html` 访问入口。

## 4. Markdown 链接写法

在对应的 Markdown 笔记中使用带 `.html` 的链接：

```markdown
[打开 AOP统一日志打印链路交互图](/archify/aop-unified-log-chain.html)
```

例如新增订单流程图：

```markdown
[打开订单流程图](/archify/order-flow.html)
```

不要写服务器完整地址，也不要链接到 `.html.md` 说明页：

```markdown
# 不推荐
[打开交互图](http://47.99.178.186:100/archify/aop-unified-log-chain.html)
[打开交互图](/Volumes/data/ideaWorkSpace/aboss-sso/aop-unified-log-chain.html.md)
```

Quartz 构建时可能会将 Markdown 中的内部链接改写成无后缀路径，例如：

```html
href="/archify/aop-unified-log-chain"
```

这是正常行为，下面的 Nginx 通用规则会自动处理该路径。

## 5. Nginx 一次性通用配置

服务器网站目录为：

```text
/www/AfykeBlog/afyke-blog
```

在 Nginx 站点配置中增加以下规则：

```nginx
# 带 .html 的地址，实际读取 Quartz 生成的无后缀文件
location ~ ^/archify/(.+)\.html$ {
    alias /www/AfykeBlog/afyke-blog/archify/$1;
    default_type text/html;
    add_header Content-Disposition inline always;
}

# Quartz 生成的无后缀地址，自动跳转到 .html 地址
location ~ ^/archify/(.+)$ {
    return 302 /archify/$1.html;
}
```

配置一次后，后续新增任何 Archify 图都不需要再次修改 Nginx。

### 5.1 两段配置分别做什么

这两段配置可以理解成“两道门”。

第一段负责真正返回 HTML 文件：

```nginx
location ~ ^/archify/(.+)\.html$ {
    alias /www/AfykeBlog/afyke-blog/archify/$1;
    default_type text/html;
    add_header Content-Disposition inline always;
}
```

当浏览器访问：

```text
/archify/aop-unified-log-chain.html
```

其中 `(.+)` 会匹配文件名，`$1` 就是匹配到的内容：

```text
$1 = aop-unified-log-chain
```

因此 Nginx 实际读取的服务器文件是：

```text
/www/AfykeBlog/afyke-blog/archify/aop-unified-log-chain
```

这个文件本身没有 `.html` 后缀，但 `default_type text/html` 会告诉浏览器它是 HTML，`Content-Disposition inline` 会告诉浏览器直接打开，而不是下载。

第二段负责把 Quartz 生成的无后缀地址跳转到 `.html` 地址：

```nginx
location ~ ^/archify/(.+)$ {
    return 302 /archify/$1.html;
}
```

Quartz 构建后，Markdown 链接可能会变成：

```text
/archify/aop-unified-log-chain
```

第二段配置会将其跳转到：

```text
/archify/aop-unified-log-chain.html
```

之后再由第一段配置读取真正的 Archify 文件。

完整访问流程如下：

```text
点击 Markdown 链接
        ↓
/archify/aop-unified-log-chain
        ↓  Nginx 自动跳转
/archify/aop-unified-log-chain.html
        ↓  Nginx 找到无后缀文件
/www/AfykeBlog/afyke-blog/archify/aop-unified-log-chain
        ↓
浏览器打开 Archify 交互图
```

其中 `(.+)` 表示任意 Archify 文件名，所以以后新增 `order-flow`、`login-sequence` 或 `payment-process` 等交互图，都可以复用这两段配置。

注意：如果已有以下配置：

```nginx
location ^~ /archify/ {
    ...
}
```

需要删除或调整它，因为 `^~` 可能阻止上面的正则规则生效。

修改配置后重新加载 Nginx，并检查：

```bash
curl -I http://47.99.178.186:100/archify/aop-unified-log-chain
```

无后缀地址应返回重定向：

```text
HTTP/1.1 302 Found
Location: /archify/aop-unified-log-chain.html
```

带 `.html` 的地址应返回网页内容：

```bash
curl -I http://47.99.178.186:100/archify/aop-unified-log-chain.html
```

重点确认：

```text
Content-Type: text/html
Content-Disposition: inline
```

## 6. 以后新增 Archify 图的流程

### 第一步：生成 HTML

将 Archify 生成的文件保存到：

```text
/Users/chenweili/Documents/quartz/content/archify/
```

例如：

```text
content/archify/order-flow.html
```

### 第二步：在 Markdown 中添加链接

```markdown
[打开订单流程图](/archify/order-flow.html)
```

### 第三步：构建 Quartz

```bash
npx quartz build
```

构建后确认文件存在：

```text
public/archify/order-flow
```

### 第四步：部署整个 public 目录

```bash
rsync -azc --delete public/ root@47.99.178.186:/www/AfykeBlog/afyke-blog/
```

如果使用 GitHub Actions，则提交并推送代码，由现有工作流自动构建和部署。

## 7. 最终访问效果

Markdown 中的链接：

```text
/archify/order-flow.html
```

Quartz 构建后可能变成：

```text
/archify/order-flow
```

Nginx 自动重定向为：

```text
/archify/order-flow.html
```

最终浏览器打开的是 Archify 交互图，而不是下载文件。

## 8. 常见问题

### 8.1 为什么本地能打开，服务器却下载？

本地 Quartz 开发服务器会根据路径自动查找和返回 HTML 文件。生产环境 Nginx 面对无后缀文件时，可能将其按普通文件处理，浏览器因此触发下载。

### 8.2 为什么不能手动给 public 文件加 `.html`？

因为 `public` 是构建产物。下一次执行 `npx quartz build` 后，手动修改会被重新生成的文件覆盖。

### 8.3 是否需要为每一张图单独修改 Nginx？

不需要。只要配置的是 `/archify/` 的通用规则，新增图只需要生成 HTML、添加 Markdown 链接并重新部署即可。

### 8.4 Archify HTML 中能不能写密码或 Token？

不能。HTML 会被发布到网站，禁止写入密码、Token、数据库连接串、内部域名和其他敏感信息。
