## 1. 💡 一句话理解

> [!tip] 核心结论
> “监听网卡”通常是指硬件、驱动和系统配合后，支持监听模式的无线网卡。监听负责接收无线帧，注入负责主动发送构造的无线帧；捕获到数据，不等于能读懂加密内容。

本文根据课程截图整理，补充 Linux 官方资料，并结合 **M 系列 Mac + Parallels + Ubuntu 24.04 ARM64** 的使用场景。资料核对日期：2026-10-25。

## 2. 🧭 理论：从普通连接到监听模式

### 2.1 先想象一个无线“会议室”

家里有一个路由器，手机和电脑都通过它联网。无线信号在空间中传播，附近的接收设备可能收到这些信号。

普通上网时，电脑主要处理与自身通信有关的数据。做无线诊断时，我们可能想观察：路由器有没有广播、设备有没有尝试连接、某个信道是否存在大量重传。

这时需要网卡把更多接收到的原始无线帧交给分析工具。

| 图中的比喻 | 实际技术含义 | 比喻的边界 |
| --- | --- | --- |
| 普通耳朵 | 网卡处于普通连接模式 | 不代表只能接收自己的单播，也会涉及广播等通信 |
| 超级耳朵 | 网卡处于监听模式 | 不会扩大到无限距离，也不能同时听遍所有信道 |
| 录音机 | 抓包软件把无线帧保存到文件 | 网卡负责收发，记录与分析主要由软件完成 |

### 2.2 普通连接模式：先加入网络，再正常上网

电脑日常连接 Wi-Fi，通常使用 **Station／Managed 模式**。它会与接入点（AP，通常就是无线路由器）完成认证和关联，再进行通信。

此时，网卡和驱动通常会过滤、处理无线帧，交给应用的内容也往往已经不是完整的原始 802.11 帧。因此，正常连接 Wi-Fi 时能抓到本机网络流量，不代表能观察周围所有无线通信。

### 2.3 监听模式：把收到的无线帧交给分析工具

**监听模式（Monitor Mode）**主要用于被动观察无线链路，不必先关联到目标接入点。

工具可以分析接收到的管理帧、控制帧、数据帧，以及驱动提供的信道、速率、信号强度等信息。具体能得到哪些信息，取决于硬件和驱动。

普通模式与监听模式是工作方式的差异，不一定是两种完全不同的硬件。有些平常用于上网的无线网卡，在合适的系统和驱动下也支持监听模式。

依据：[Linux Wireless 的无线工作模式说明](https://wireless.docs.kernel.org/en/latest/en/users/documentation/modes.html)。

## 3. ⚙️ 理论：监听、注入与加密的边界

### 3.1 为什么“能听所有对话”不准确

截图用“超级耳朵”帮助理解，但实际捕获存在几层限制：

- **频段限制**：只支持 2.4 GHz 的网卡无法接收 5 GHz 无线帧。
- **信道限制**：单个无线射频通常只能在某一时刻观察一个信道配置。跳频扫描时，会漏掉离开某个信道期间的通信。
- **接收条件限制**：距离、遮挡、干扰、信号强度和设备能力都会影响接收，监听也可能丢帧。
- **加密限制**：收到 WPA2／WPA3 加密的数据帧，不代表已经得到其中的明文。

即使某一层 Wi-Fi 加密能够在具备相应密钥等条件下解密，HTTPS 等应用层加密仍然是另一层保护。无线帧、网页内容和聊天内容不是同一个层次。

> [!warning] 捕获不等于破解
> 监听网卡不会自动显示 Wi-Fi 密码，也不会自动把附近人的聊天内容变成明文。

### 3.2 数据包注入：从“听”变成“发”

**数据包注入（Packet Injection）**指通过工具和驱动，主动发送构造的无线帧。这里更精确的对象是 802.11 无线帧，“数据包注入”是常见叫法。

| 能力 | 在做什么 | 常见用途 |
| --- | --- | --- |
| 监听 | 被动接收、观察无线帧 | 无线故障排查、协议学习、覆盖与重传分析 |
| 注入 | 主动发送构造的无线帧 | 在自有或授权实验环境验证协议与设备行为 |

支持监听，不自动等于支持可靠注入；能够发送某种帧，也不保证接收方接受或产生预期行为。Linux 的 mac80211 可以支持通过监听接口发送帧，但仍需具体硬件和驱动配合。

依据：[Linux Wireless 对 Monitor Mode 与 Packet Injection 的说明](https://wireless.docs.kernel.org/en/latest/en/users/documentation/modes.html)。

### 3.3 图中的“必备功能”要按用途理解

如果只是分析自己网络的无线信道和帧，重点是监听能力，不一定需要注入。

如果实验需要主动构造无线帧，才要进一步验证注入能力。不能只看商品标题中的“监听＋注入”，还要看实物芯片、驱动版本、系统内核和实际测试结果。

## 4. 📡 网卡选型：看芯片，也看驱动

### 4.1 三种常见芯片怎么区分

| 芯片 | 频段 | Linux 驱动情况 | 选型时关注什么 |
| --- | --- | --- | --- |
| RTL8812AU | 2.4 GHz、5 GHz | 存在支持监听和注入的第三方驱动；不同内核的支持路径可能变化 | 检查当前内核、ARM64 编译支持和所需功能，不照搬旧教程 |
| AR9271 | 2.4 GHz | 使用 ath9k_htc，需相应固件 | 不适合观察 5 GHz 网络 |
| MT7612U | 2.4 GHz、5 GHz | 使用内核中的 mt76 家族驱动，USB 对应 mt76x2u | 通常少一步手动编译，但仍需驱动模块、固件和 USB 识别正常 |

RTL8812AU 与 AR9271 是截图提到的芯片，MT7612U 是结合前面的购买讨论补充的选项。它们不是完整产品型号：不同商家可能使用不同天线、电路和 USB 标识，甚至更换芯片，不能仅凭外壳判断。

资料：[RTL8812AU 驱动项目](https://github.com/aircrack-ng/rtl8812au)、[ath9k_htc 文档](https://wireless.docs.kernel.org/en/latest/en/users/drivers/ath9k_htc.html)、[MediaTek 无线驱动文档](https://wireless.docs.kernel.org/en/latest/en/users/drivers/mediatek.html)。

### 4.2 MT7612U 为什么常被称为“免驱”

“免驱”是指系统通常已经提供驱动，用户不用另行下载安装，并不是硬件不需要驱动。

可以把驱动理解为系统与硬件之间的翻译：Ubuntu 或 Kali 已经带了翻译，插入后系统就有机会自动识别。驱动模块或固件缺失时，仍然需要补齐。

因此，商品写“Kali 免驱”不能自动推导出所有 Linux 镜像都可即插即用，更不能推导出 macOS 原生支持。

### 4.3 5 GHz、5G 与 1200M 分别是什么

- **5 GHz**：Wi-Fi 的工作频段，与手机运营商的 5G 移动网络不是一回事。
- **2.4 GHz＋5 GHz**：支持两种频段，不代表单个无线射频能同时监听两个频段的全部通信。
- **1200M／AC1200**：常见商品速率等级，通常综合不同频段的标称链路速率，不代表实际下载速度，也不是监听性能保证。

## 5. 🚀 实践：在 Mac 虚拟机里检查网卡

### 5.1 前置准备

沿用已有环境：M 系列 Mac、Parallels、Ubuntu 24.04 ARM64，以及一只实物芯片确认过的 USB 无线网卡。必要时使用支持数据传输的 USB-C 转接器。

Ubuntu 是通用 Linux 系统；Kali 也是 Linux 系统，只是预装较多安全测试工具。本节无需换装 Kali。

在 Parallels 的「设备 → USB 与蓝牙」中，把网卡交给 Ubuntu。USB 直通后由 Ubuntu 驱动设备，macOS 无需为这只网卡安装无线驱动。

```text
USB 无线网卡
    ↓ Parallels USB 直通
Ubuntu ARM64
    ↓ Linux 驱动和固件
无线接口
    ↓ 抓包或诊断工具
观察与分析
```

参考：[Parallels 外部设备连接说明](https://kb.parallels.com/en/122993)。

### 5.2 共享网络与 USB 直通有什么不同

| 方式 | Ubuntu 看到什么 | 适合什么 |
| --- | --- | --- |
| Parallels 共享网络 | 通常是虚拟以太网接口 | 上网、下载软件、访问服务 |
| USB 无线网卡直通 | 实际 USB 设备；驱动成功后出现无线接口 | 操作该网卡的无线信道、检查监听能力 |

Mac 通过 Wi-Fi 上网，不代表 Ubuntu 就直接拥有 Mac 内置无线网卡的控制权。共享网络可以保留用于下载依赖，外接无线网卡用于无线实验。

### 5.3 完整检查：从设备到能力

以下命令在 **Ubuntu 终端**执行，用于确认识别情况；不会主动发送构造的无线帧。

如果没有这些工具，先通过共享网络安装：

```bash
# 更新软件索引，安装 USB 查询工具和无线接口查询工具。
sudo apt update
sudo apt install usbutils iw
```

然后按顺序检查：

```bash
# 确认 Ubuntu 的架构；M 系列 Mac 的 ARM64 虚拟机通常输出 aarch64。
uname -m

# 查看内核版本，后续判断驱动兼容性需要它。
uname -r

# 查看 Ubuntu 是否拿到了 USB 设备。
lsusb

# 查看驱动是否已注册无线接口，接口名可能是 wlan0 或 wlx 开头。
iw dev

# 查看无线硬件声明的能力，重点找 Supported interface modes。
iw list
```

结果按层理解：

| 结果 | 说明 | 下一步 |
| --- | --- | --- |
| lsusb 没有对应设备 | 尚未成功交给 Ubuntu，或连接存在问题 | 检查 Parallels 的 USB 归属、转接器与供电 |
| lsusb 有设备，iw dev 无无线接口 | USB 已识别，但无线驱动可能未成功工作 | 根据设备 ID 和内核版本查驱动、固件及日志 |
| iw dev 有无线接口 | 驱动已经注册接口 | 再检查 iw list 的能力和频段 |
| Supported interface modes 包含 monitor | 驱动声明支持监听模式 | 仍需在实际环境验证抓帧稳定性 |

`iw list` 不包含 `monitor` 时，不能因为商家写“监听网卡”就认为该环境已支持。包含 `monitor` 也不证明注入能力已经验证；多块无线设备同时存在时，要对应到实际网卡的 PHY。

### 5.4 MT7612U 未识别时怎么排查

```bash
# 查看当前内核是否提供 MT7612U 对应的模块信息。
modinfo mt76x2u

# 查看近期内核消息，查找 USB、驱动或固件加载失败原因。
sudo dmesg | tail -n 80
```

- `Module mt76x2u not found`：当前内核对应的模块可能未安装或未启用，需按实际 Ubuntu 内核包处理。
- 日志出现固件加载失败：根据报错中的文件名检查固件；Ubuntu 中通常由 `linux-firmware` 软件包提供相关文件。
- 命令提示不存在：先安装对应查询工具；不要把工具缺失当成网卡不兼容。

本节只完成识别和能力检查，没有切换监听模式，也没有实测捕获和注入。排查时不要同时安装多个来源的驱动，以免增加冲突。

## 6. 📌 快速回顾

- 普通连接模式用于正常加入 Wi-Fi；监听模式用于观察接收到的无线帧。
- “超级耳朵”只是比喻，实际受频段、信道、接收条件和加密限制。
- 监听负责接收，注入负责主动发送，两种能力需要分别确认。
- 选型看芯片、系统、驱动与固件；“免驱”只是通常不用手动装驱动。
- Mac 虚拟机里使用外接无线网卡，先确认 USB 直通，再确认无线接口和能力。

记忆句：**先让虚拟机拿到设备，再让驱动认出网卡，最后验证需要的功能。**
