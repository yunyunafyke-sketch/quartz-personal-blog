**Full GC（简称 FGC）是 Java 虚拟机对整个堆内存进行的一次较全面的垃圾回收**，目的是清理不再使用的对象，腾出内存。具体回收范围和方式取决于垃圾收集器。

可以把内存想成一间仓库：

- **普通的 Young GC**：主要清理新生代，也就是临时物品区，通常比较快。
- **Full GC**：清理范围更大，通常涉及老年代，耗时往往更长，而且常伴随应用线程暂停，表现为接口变慢、程序卡顿。

你这段话里的过程可以这样理解：

**一次加载大量文件数据 → 大量对象占用内存 → 内存紧张 → JVM 尝试通过 Full GC 腾空间。**

但有一个关键点：**垃圾回收只能清理不再被使用的对象。** 如果待处理数据一直保存在列表或队列里，程序还引用着它们，Full GC 也不能把它们清掉。于是可能反复回收却腾不出足够空间，最终出现 **OOM（内存溢出）**。

因此，**FGC 是回收动作，OOM 是内存不足导致的错误**。偶尔发生 FGC 不一定有问题，频繁发生才需要关注。导入时采用分批读取、分批处理，并及时释放已处理数据，通常能减轻这种压力。
