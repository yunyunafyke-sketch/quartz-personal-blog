## 1. 先记住三句话

- **引用拷贝**：不创建新对象，只复制引用，两个变量指向同一个对象。
- **浅拷贝**：创建新的外层对象，但内部引用类型字段仍指向原来的对象。
- **深拷贝**：创建新的外层对象，并复制需要隔离的内部可变对象，让双方修改互不影响。


下面用“员工及其地址”的例子理解：员工有年龄 `age`、姓名 `name` 和地址 `address`。地址本身也是一个可以修改的对象。

## 2. 三种拷贝的对象关系

```text
引用拷贝：
 a ──┐
     ├──→ 员工对象 ──→ 地址对象
 b ──┘

浅拷贝：
 a ──→ 员工对象 A ──┐
                   ├──→ 同一个地址对象
 b ──→ 员工对象 B ──┘

深拷贝：
 a ──→ 员工对象 A ──→ 地址对象 A
 b ──→ 员工对象 B ──→ 地址对象 B
```

| 对比项 | 引用拷贝 | 浅拷贝 | 深拷贝 |
| --- | --- | --- | --- |
| 是否创建新的员工对象 | 否 | 是 | 是 |
| `a == b` | `true` | `false` | `false` |
| `a.address == b.address`（地址非空） | `true` | `true` | `false` |
| 修改 `b.age`，`a.age` 是否受影响 | 是 | 否 | 否 |
| 修改 `b.address.city`，`a.address.city` 是否受影响 | 是 | 是 | 否 |
| 给 `b.address` 换一个新地址，`a.address` 是否受影响 | 是 | 否 | 否 |

这里的深拷贝会复制地址对象；不可变对象（例如 `String`）可以安全共享，不必为了“深”而全部重新创建。

## 3. 拆成三个独立的类，看清每一步

把下面三个文件放在同一个目录中，运行 `CopyDemo` 的 `main()` 方法即可。每个类单独放一个文件，不使用内部类。

| 文件 | 负责什么 |
| --- | --- |
| `Address.java` | 表示地址，保存城市 |
| `Employee.java` | 表示员工，保存年龄、姓名和地址，并提供拷贝方法 |
| `CopyDemo.java` | 创建对象，分别演示三种拷贝 |

为了集中理解拷贝，示例中的字段直接访问，暂不引入 getter、setter。

### 3.1 地址类：Address.java

一个 `Address` 对象表示一份地址。每次 `new Address("上海")` 都会创建一个新的地址对象。

```java
public class Address {
    String city;

    public Address(String city) {
        this.city = city;
    }
}
```

### 3.2 员工类：Employee.java

`address` 字段保存的是地址对象的引用。重点比较两个方法：

- `shallowCopy()`：直接把原来的 `address` 交给新员工，所以两个员工共享地址。
- `deepCopy()`：先用 `new Address(...)` 创建新地址，再交给新员工，所以地址也独立。

```java
public class Employee {
    int age;
    String name;
    Address address;

    public Employee(int age, String name, Address address) {
        this.age = age;
        this.name = name;
        this.address = address;
    }

    // 浅拷贝：创建新员工，但继续使用原来的地址对象。
    public Employee shallowCopy() {
        Employee copiedEmployee = new Employee(age, name, address);
        return copiedEmployee;
    }

    // 深拷贝：先复制地址，再创建使用新地址的员工。
    public Employee deepCopy() {
        Address copiedAddress = null;
        if (address != null) {
            copiedAddress = new Address(address.city);
        }

        Employee copiedEmployee = new Employee(age, name, copiedAddress);
        return copiedEmployee;
    }
}
```

这里的 `shallowCopy`、`deepCopy` 是我们自己定义的方法名。真正决定拷贝深浅的是方法里面的代码。

### 3.3 运行示例：CopyDemo.java

每一种拷贝都重新创建一份原始员工数据，避免前一个例子的修改影响下一个例子。可以先只看第一段，再依次看浅拷贝和深拷贝。

```java
public class CopyDemo {
    public static void main(String[] args) {
        // 1. 引用拷贝：只有一个员工对象。
        Employee a = new Employee(25, "小陈", new Address("上海"));
        Employee b = a;
        System.out.println(a == b);                 // true
        b.age = 30;
        b.address.city = "杭州";
        System.out.println(a.age);                  // 30
        System.out.println(a.address.city);         // 杭州

        // 2. 浅拷贝：员工独立，地址共享。
        a = new Employee(25, "小陈", new Address("上海"));
        b = a.shallowCopy();
        System.out.println(a == b);                 // false
        System.out.println(a.address == b.address); // true
        b.age = 30;
        b.name = "小李";
        b.address.city = "杭州";
        System.out.println(a.age);                  // 25
        System.out.println(a.name);                 // 小陈
        System.out.println(a.address.city);         // 杭州

        // 替换 b 的地址字段，不会替换 a 的地址字段。
        b.address = new Address("北京");
        System.out.println(a.address.city);         // 杭州
        System.out.println(b.address.city);         // 北京

        // 3. 深拷贝：员工和地址都独立。
        a = new Employee(25, "小陈", new Address("上海"));
        b = a.deepCopy();
        System.out.println(a == b);                 // false
        System.out.println(a.address == b.address); // false
        b.age = 30;
        b.address.city = "杭州";
        System.out.println(a.age);                  // 25
        System.out.println(a.address.city);         // 上海
    }
}
```

阅读时先看 `a == b`，判断员工是不是同一个对象；再看 `a.address == b.address`，判断地址是不是同一个对象；最后看修改后的输出。

## 4. 最容易混淆的几个地方


### `String` 是引用类型，为什么改姓名不影响原对象？

浅拷贝后，两个员工的 `name` 最初可以指向同一个字符串。

但 `String` 不可变，`b.name = "小李"` 是替换 `b` 的字段引用，并没有修改原来的字符串，也没有修改 `a.name`。

所以，**不能只用字符串字段是否相互影响，判断是不是深拷贝**。要观察内部可变对象，例如这里的 `Address`。

### `clone()` 自动完成深拷贝吗？

不会。`Object.clone()` 按字段复制内容：基本类型复制值，引用类型复制引用，因此它执行的是浅拷贝。若要通过它实现深拷贝，需要继续复制内部可变对象。普通类使用 `super.clone()` 还需要实现 `Cloneable`，否则会抛出 `CloneNotSupportedException`。参见 [Object.clone() 官方说明](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Object.html#clone())。

### 只要用了 `new`，就是深拷贝吗？

不是。示例中的 `shallowCopy()` 也用了 `new Employee(...)`，但仍然共享地址。判断依据是**需要隔离的可变对象是否仍被共享**，不是有没有 `new`。

如果地址里还有可变的列表，列表元素里还有可变对象，也要沿着这条引用关系继续处理。复杂对象图还需要考虑循环引用，以及同一个对象被多处引用的情况。

## 5. 怎么判断、怎么选择

判断时按顺序看：

1. 外层对象是不是同一个？若是，只复制了引用。
2. 外层对象不同，内部可变对象是否仍然共享？若是，没有完成这部分数据的深拷贝。
3. 需要独立修改的数据是否都已隔离？若是，达到了业务需要的深拷贝效果。

选择时看目的：希望两处操作同一份数据，就共享引用；只需要独立的外层字段、允许内部对象共享，就使用浅拷贝；需要一份能独立修改的副本，就对相关可变数据做深拷贝。

> 记忆口诀：引用拷贝共用对象，浅拷贝只复制外层，深拷贝继续复制内部可变对象。
