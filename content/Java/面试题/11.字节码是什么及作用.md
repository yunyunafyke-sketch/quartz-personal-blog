## 一、💡 一句话理解

> [!tip] 核心结论
> 字节码是 Java 源代码编译后生成的 JVM 指令，通常保存在 `.class` 文件中。它不是 CPU 直接执行的机器码，而是 Java 源代码和不同操作系统之间的“中间语言”。

```text
.java 源代码 → javac 编译 → .class 字节码 → JVM 执行
```

## 二、🧭 理论：它是什么

### 2.1 核心概念

假设要把同一个 Java 程序分别部署到 Windows、Linux 和 macOS。

Java 编译器不会直接生成某一种 CPU 的机器码，而是先生成统一的字节码。不同平台安装各自的 JVM，再由 JVM 负责执行这份字节码。

| 场景角色 | 真实技术对象 |
| --- | --- |
| Java 源文件 | `.java` 文件 |
| 翻译员 | `javac` 编译器 |
| 通用说明书 | `.class` 字节码文件 |
| 各平台执行者 | JVM |

> [!info] 注意
> `.class` 文件不只包含字节码指令，还包含常量池、字段、方法等信息。

## 三、⚙️ 理论：它有什么作用

### 3.1 实现跨平台

同一份字节码可以交给不同平台的 JVM 执行，这就是“一次编译，到处运行”的基础。

### 3.2 连接源码和机器码

JVM 可以解释执行字节码，也可以通过 JIT 即时编译器把热点字节码编译成本地机器码，提高运行效率。

### 3.3 支持运行前检查

JVM 在执行代码前会验证 `.class` 文件的结构和字节码是否合法，降低非法指令破坏运行环境的风险。

## 四、🚀 实践：查看字节码

### 4.1 最小验证

准备一个 `Hello.java`：

```java
public class Hello {
    public static void main(String[] args) {
        int result = 1 + 2;
        System.out.println(result);
    }
}
```

编译并查看字节码：

```bash
javac Hello.java
javap -c Hello
```

`javac` 会生成 `Hello.class`，`javap -c` 会反汇编其中的方法，显示 `iconst`、`istore`、`invokevirtual` 等 JVM 指令。

## 五、🎤 面试时怎么说

### 5.1 30 秒标准回答

字节码是 Java 源代码经过 `javac` 编译后生成的 JVM 指令，通常保存在 `.class` 文件中。它不是特定 CPU 的机器码，而是一种平台无关的中间格式。不同操作系统通过各自的 JVM 执行同一份字节码，因此 Java 能够实现跨平台。JVM 还可以对字节码进行安全验证，并通过解释执行或 JIT 编译将它转成机器码运行。

## 六、📌 总结

- 字节码是 JVM 能理解的指令。
- 字节码通常保存在 `.class` 文件中。
- JVM 屏蔽了不同操作系统和硬件的差异。
- 字节码最终需要由 JVM 解释执行或编译成机器码。

记忆句：**源码先编成字节码，字节码再交给 JVM，JVM 负责适配不同平台。**
