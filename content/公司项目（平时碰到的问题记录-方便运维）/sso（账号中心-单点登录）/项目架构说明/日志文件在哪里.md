## 一、💡 一句话理解

> [!tip] 核心结论
> 本项目把日志目录写成了相对路径 `./logs/aboss-sso`。`./` 以 JVM 的启动工作目录（`user.dir`）为基准，因此日志并不固定在源码目录或 Jar 目录；从哪里启动，日志通常就生成到那个目录下的 `logs/aboss-sso/` 中。

日志配置、日志分类以及业务日志的来源，可结合 [[aboss-sso项目架构]] 和 [[该项目AOP理解]] 一起阅读。

## 二、🧭 理论：日志文件由谁决定

### 2.1 配置文件只提供“相对规则”

项目实际配置文件是：

```text
start/src/main/resources/log4j2.xml
```

它定义了三层变量：

```xml
<!-- 应用名：用于给不同应用划分日志目录 -->
<property name="APP_NAME" value="aboss-sso"/>

<!-- ./ 表示相对路径；不是 log4j2.xml 文件所在目录 -->
<property name="LOG_HOME" value="./logs/${APP_NAME}"/>

<!-- COMMON-APPENDER 当前正在写入的普通日志文件 -->
<RollingFile name="COMMON-APPENDER"
             fileName="${LOG_HOME}/common-default.log">
```

Log4j2 会先进行属性替换：

```text
${APP_NAME} = aboss-sso
${LOG_HOME} = ./logs/aboss-sso

${LOG_HOME}/common-default.log
= ./logs/aboss-sso/common-default.log
```

这一步只得到相对路径，尚未决定磁盘中的唯一绝对位置。Log4j2 的 `${...}` 是配置属性复用机制；官方文档将其称为 property substitution。[Log4j2 Configuration](https://logging.apache.org/log4j/2.x/manual/configuration.html)

### 2.2 `./` 的真正基准是 `user.dir`

Java 的 `user.dir` 系统属性表示当前工作目录。Unix/macOS 下，Java 把相对路径转换为绝对路径时，会以该目录作为基准。[Java File API](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/io/File.html)

因此可以把本项目的规则记成：

```text
真实日志目录 = System.getProperty("user.dir") + "/logs/aboss-sso"
```

注意：`user.dir` 通常是执行 `java` 命令或 IDE 启动配置指定的目录；它不是 `log4j2.xml` 的目录，也不是自动等于项目根目录。

## 三、⚙️ 理论：本项目的日志怎样被送到普通文件

### 3.1 普通业务日志的路由

项目为 `com.aliyun.fsi.insurance` 包配置了专用异步 Logger：

```xml
<!-- 本项目业务代码所在的根包 -->
<AsyncLogger name="com.aliyun.fsi.insurance" additivity="false" level="${LOG_LEVEL}">
    <!-- ERROR 日志额外写入错误文件 -->
    <AppenderRef ref="ERROR-APPENDER"/>
    <!-- 所有达到该 Logger 等级的业务日志写入普通文件 -->
    <AppenderRef ref="COMMON-APPENDER"/>
    <!-- 同时输出到控制台 -->
    <AppenderRef ref="STDOUT-APPENDER"/>
</AsyncLogger>
```

`COMMON-APPENDER` 没有额外的等级过滤器。因此，命中这个业务包 Logger 的 DEBUG、INFO、WARN、ERROR 日志都会写入 `common-default.log`。ERROR 日志还会额外被 `ERROR-APPENDER` 写入 `common-error.log`，这是有意保留两份用途不同的记录，不是重复写错了。

此外，未命中专用 Logger 的日志会交给 `AsyncRoot`；Root 也引用了 `COMMON-APPENDER`，但其最低等级是 INFO。

### 3.2 AOP INFO 日志为什么也在这里

`LogAopConfig` 位于包：

```text
com.aliyun.fsi.insurance.sso.config
```

它使用 Lombok 的 `@Slf4j` 生成类级 Logger，并在环绕通知中调用：

```java
// 目标业务方法执行完成后，记录类名、方法、入参与返回值、耗时
log.info("请求类 : {}.{} 请求参数 : {} 返回参数 : {} 耗时 : {} ms",
        methodSignature.getDeclaringTypeName(), methodSignature.getName(),
        JSON.toJSONString(joinPoint.getArgs()),
        JSON.toJSONString(result),
        System.currentTimeMillis() - startTime);
```

这个 Logger 名属于 `com.aliyun.fsi.insurance` 的子包，因此会命中上面的业务异步 Logger，随后被送到 `COMMON-APPENDER`，最后写入 `common-default.log`。

路径链路可以这样理解：

```text
业务方法 / LogAopConfig.log.info(...)
        ↓
com.aliyun.fsi.insurance 异步 Logger
        ↓
COMMON-APPENDER
        ↓
${LOG_HOME}/common-default.log
        ↓
./logs/aboss-sso/common-default.log
```

## 四、🚀 实践：确认本次启动的真实日志位置

### 4.1 前置准备

只需要在当前应用进程中读取 JVM 工作目录。无需修改 Log4j2 配置。

### 4.2 可以拿来干什么

当 IDE、Maven 或服务器脚本的启动目录不同，日志可能看起来“消失”了。读取 `user.dir` 可以直接定位本次启动生成的那一份日志。

```java
// 临时输出 JVM 的启动工作目录，用于拼出日志的绝对路径
System.out.println("user.dir = " + System.getProperty("user.dir"));
```

若输出为：

```text
/Volumes/data/ideaWorkSpace/aboss-sso/start
```

那么普通日志文件就是：

```text
/Volumes/data/ideaWorkSpace/aboss-sso/start/logs/aboss-sso/common-default.log
```

### 4.3 两种实际启动结果

工作区中已存在以下两套日志目录，说明历史启动目录至少有两种：

| JVM 工作目录 | 普通日志绝对路径 |
| --- | --- |
| `/Volumes/data/ideaWorkSpace/aboss-sso` | `/Volumes/data/ideaWorkSpace/aboss-sso/logs/aboss-sso/common-default.log` |
| `/Volumes/data/ideaWorkSpace/aboss-sso/start` | `/Volumes/data/ideaWorkSpace/aboss-sso/start/logs/aboss-sso/common-default.log` |

如果希望所有环境都写到唯一固定的位置，应把 `LOG_HOME` 改成部署约定的绝对目录，或由启动脚本统一工作目录。改变日志目录属于配置变更，应先确认服务器的目录权限、磁盘容量和采集规则。

### 4.4 日志滚动与保留规则

普通日志的当前文件是：

```text
common-default.log
```

它会在每天或文件达到 500MB 时滚动为：

```text
common-default-YYYY-MM-DD_序号.log
```

配置同时规定最多保留 5 个滚动文件，并在滚动时删除超过 2 天的 `.log` 文件。这里没有配置压缩，因此归档文件仍是普通 `.log` 文件。

## 五、📌 总结

- `LOG_HOME` 最终值是 `./logs/aboss-sso`，其中 `./` 是相对路径。
- 相对路径由 JVM 的 `user.dir` 决定，启动目录不同，日志绝对位置就不同。
- 业务包和 `LogAopConfig` 的 INFO 日志都会被路由到 `COMMON-APPENDER`，写入 `common-default.log`。
- ERROR 会同时进入普通日志和错误日志，便于按全量链路或按异常快速排查。
- 排查“日志在哪里”时，先确认启动方式，再输出 `System.getProperty("user.dir")`。
