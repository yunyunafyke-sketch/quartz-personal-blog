# 了解概念

> 先记住一句话：**条线就是给业务分组的标签。** UAT 中的“电融（`TX_XK`）”“理赔（`TX_LP`）”“车商（`TX_CS`）”就是不同条线；项目、外包人员和协议都会记录自己属于哪个条线。

> **电融怎么理解：**
>
> - 电融 = 一类车险渠道业务
> - `TX_XK` = 系统里给这类业务的编码
> - 电融项目 = 服务这类车险渠道业务的具体项目

从条线往下看，可以这样理解这些数据的层级关系：

```text
条线：电融
  └─ 项目：浙江分公司电融服务外包项目
       ├─ 人员：该项目下办理入场的外包人员
       └─ 协议：与该业务相关的协议
```

## 1. 先认识三个词

| 词 | 大白话解释 | 小例子 |
| --- | --- | --- |
| 条线 | 一类业务的归属标签 | UAT 中“浙江分公司电融服务外包项目”属于电融条线（`TX_XK`） |
| 条线管理员 | 负责某个条线、可查看该条线数据的人 | 被授权的电融条线管理员只看电融相关数据 |
| 项目分类 | 在某条线内给项目再分个小类 | UAT 中电融条线当前配置了分类值 `111` |

可以把它理解成一个办公园区：条线是不同楼栋，项目分类是楼栋里的不同部门，条线管理员是被允许进入某栋楼的人。

### UAT 数据小快照

本次只读查询时，电融条线（`TX_XK`）已有 **135 个项目、3409 名外包人员**；理赔条线有 58 个项目和 125 名外包人员。这说明条线不是空的配置项，而是实际业务数据归属的重要标记。

## 2. 这个模块是做什么的

条线模块负责三件事：

1. 建立并维护条线，例如维护“电融（`TX_XK`）”。
2. 给条线配置管理员，例如授权某个账号负责电融条线。
3. 给条线配置可用的项目分类，例如电融条线当前可使用分类值 `111`。

它不负责创建项目、办理人员入场或签协议；这些业务由各自模块完成。条线模块只提供统一的“归属标签”和“谁能看”的规则。

**UAT 例子：** 人力同事维护好“电融（`TX_XK`）”后，项目模块就可以把“浙江分公司电融服务外包项目”归到该条线；人员和协议模块也使用同一个条线编码，不需要各自重新定义“电融”是什么。

## 3. 它是怎么工作的

### 3.1 新增、修改和删除条线

- 新增条线时，需要填写唯一的条线编码和名称。
- 平时可以改名称，例如把“电融”展示名称调整为更准确的业务名称。
- **不建议改编码**：编码会被项目、人员和协议长期引用，就像身份证号，改了会找不到原来的关联数据。
- 删除条线前，系统会先检查是否已经关联项目或计划；有数据在用时不能删除。

**UAT 例子：** 电融条线目前已关联 135 个项目和 3409 名外包人员，显然不能直接删除。若只是名称变了，改名称即可，已有项目仍可通过 `TX_XK` 找回正确归属。

### 3.2 谁能看到哪些数据

条线管理员关系决定普通业务人员的可见范围：

```text
某账号是电融条线管理员
  → 只能查看电融条线的项目、人员等数据

人力同事或超管
  → 可以查看多个条线的数据
```

如果普通用户没有被配置为任何条线管理员，通常就没有条线数据可查看。

这里还有一套“组织 ACL 权限”。它控制的是“能看哪个组织的数据”，不是“能看哪个条线的数据”。实际查询时，两种范围需要一起满足。

**结合真实项目理解：** “浙江分公司电融服务外包项目”既属于电融条线，也属于一个具体运营机构。某账号即使拥有电融条线权限，仍需同时具备该机构的数据权限，才能查看这个项目。

### 3.3 项目分类为什么要挂在条线下

项目分类不是所有条线共用的。每条线只维护自己可用的分类，这样可避免业务人员选错分类。

**UAT 例子：** 电融条线当前配置的项目分类为 `111`。创建电融项目时，页面应从电融条线自己的分类配置中取值，而不是随意使用其他条线的分类。

### 3.4 条线和项目的关系

条线和分公司是两条**并列的维度**：

- 条线回答“做哪类业务”，例如电融。
- 分公司回答“哪个机构在做”，例如浙江分公司。
- 项目把两者连接起来，表示“浙江分公司要做一项电融业务的外包用工事项”。

> **结论：条线与分公司是并列维度，项目才是两者的交点；电融条线可被浙江、天津等多个机构使用。**

```text
浙江分公司 ─┐
             ├─ 浙江分公司电融服务外包项目
电融条线 ───┘
```

因此，条线不是挂在浙江分公司下面；它是公司统一维护的业务分类，可以被多个分公司使用。UAT 中电融条线除了有“浙江分公司电融服务外包项目”，也有天津等机构的项目记录。

项目额度、审批状态、人员入场、项目变更等具体内容，后续在“项目模块”笔记中单独说明。

## 4. 它与其他模块怎么配合

项目、人员和协议模块都会记录条线编码，用来说明自己属于哪类业务；它们的具体流程分别在各自模块笔记中说明。

在这里只需要记住：**条线模块提供统一的业务分类和可见范围，其他模块引用它。**

## 5. 使用时最需要注意什么

1. **条线编码要稳定。** 名称可以调整；编码一旦变动，项目、人员和协议的关联可能受到影响。
2. **删除前先看有没有在使用。** 有项目、计划或其他业务数据关联时，应先处理引用关系。
3. **查询条件不能替代权限。** 某账号即使手动选择理赔条线，系统也应检查他是否拥有理赔条线权限。
4. **别把条线权限和组织权限混为一谈。** 条线回答“负责哪类业务”，组织回答“负责哪个机构”；通常两者都要满足。

## 6. 最后总结

条线模块像 HRMS 的“业务地图”：它把项目、人员和协议归到正确的业务组，再通过管理员关系划出谁能看哪些数据。理解它时，只要抓住三个问题：**这条数据属于哪个条线？谁负责这个条线？这个条线可以使用哪些项目分类？**
