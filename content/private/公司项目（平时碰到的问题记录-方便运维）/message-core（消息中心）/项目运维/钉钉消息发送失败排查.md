# 钉钉消息发送失败排查

## 一、分类原则

以“钉钉是否已经成功受理发送任务并返回 `taskId`”作为排查边界：

| 现象 | 分类 | 说明 |
| --- | --- | --- |
| 请求尚未调用钉钉就失败 | 我们自己系统发送失败 | 消息组装、配置查询、账号转换等本地处理失败 |
| 调用钉钉时发生网络或超时异常 | 我们自己系统发送失败 | 我方没有拿到明确受理结果，不能认定钉钉已经接收任务 |
| 钉钉发送接口明确返回失败 | 钉钉接口拒绝 | 直接记录钉钉 `errcode`、`errmsg`；根因也可能是我方参数或配置错误 |
| 钉钉返回成功并生成 `taskId`，但异步结果存在失败人员 | 钉钉实际投递失败 | 钉钉已受理任务，但没有成功投递给全部接收人 |
| 查询异步发送结果接口异常 | 我们自己系统查询失败 | 此时只能说明结果查询失败，不能直接判断消息是否投递失败 |

简单判断：**没有 `taskId`，优先排查我们自己的系统；有 `taskId`，优先查询钉钉异步发送结果。**

## 二、我们自己系统发送失败

这类失败通常发生在请求被钉钉成功受理之前。

### 1. 消息组装和参数校验失败

- 消息类型不是系统支持的 `text`、`link`、`template`、`image`、`markdown` 或 `action_card`。
- 标题、正文、链接、卡片按钮标题等必填参数为空。
- Link 或 ActionCard 的链接没有以 `http://`、`https://`、`//` 或 `/` 开头。
- 消息正文不是合法 JSON，无法转换成对应消息对象。
- 模板内容或模板变量解析失败。
- `agentId` 为空或不是合法数字。

### 2. 接收人转换失败

- 账号中心 RPC 查询异常或没有返回账号数据。
- 业务账号没有绑定钉钉 `userId`。
- 所有接收人转换完成后，钉钉 `userId` 列表为空。

说明：如果我方成功提交了某个 `userId`，但钉钉异步结果判定它无效，则归入“钉钉实际投递失败”。

### 3. 渠道或应用配置处理失败

- 消息渠道配置不存在。
- 我方没有配置 `appKey`、`appSecret` 或 `agentId`。
- 获取 token 的调用发生异常，或者没有拿到有效的 `accessToken`。

说明：如果配置值存在，但钉钉明确返回凭证错误、应用无权限等错误，则表现为“钉钉接口拒绝”，根因仍需要修改我方配置。

### 4. 图片预处理失败

- `imageUrl` 为空或 URL 格式错误。
- 图片地址无法访问、连接超时或需要额外鉴权。
- 下载图片时发生异常。
- 上传媒体前的文件构造失败。

如果文件已经提交到钉钉，但钉钉因格式、大小或其他规则拒绝，则归入“钉钉接口拒绝”。

### 5. 系统和基础设施异常

- 调用钉钉接口时发生 DNS、网络、证书、代理或连接超时异常。
- MQ 消费异常。
- 数据库查询或消息状态更新异常。
- 账号中心 RPC 异常。
- 程序空指针、数据转换异常等代码问题。

这类异常通常会将消息标记为失败，并由重试任务再次发送，直到达到最大重试次数。

## 三、钉钉发送失败

### 1. 钉钉发送接口直接拒绝

调用发送接口后，如果响应的 `isSuccess()` 为 `false`，属于钉钉接口明确拒绝。常见原因包括：

- `accessToken` 无效或过期。
- `appKey`、`appSecret`、`agentId` 与应用不匹配。
- 应用被停用或没有发送工作通知的权限。
- 请求参数不符合钉钉接口规则。
- 接收人为空，对应错误码 `1430000`。
- 消息包含违禁内容，对应错误码 `1430002`。
- 图片格式、大小或媒体内容不符合钉钉限制。
- 钉钉服务端异常。

这类情况必须保留钉钉原始的 `errcode` 和 `errmsg`，否则很难判断真实原因。

### 2. 钉钉受理成功但实际投递失败

发送接口返回成功和 `taskId`，只代表钉钉受理了任务。查询异步发送结果时，出现以下数据仍表示实际投递失败：

- `invalidUserIdList`：无效的钉钉 `userId`。
- `forbiddenList`：用户因具体限制被禁止推送。
- `forbiddenUserIdList`：发送过于频繁或超量，被流控后未发送的用户。
- `failedUserIdList`：钉钉明确标记发送失败的用户。
- `invalidDeptIdList`：无效的部门 ID。
- 用户不在当前企业或不在应用可见范围内。

### 3. 发送频率或数量超限

| 错误码 | 原因 | 处理建议 |
| --- | --- | --- |
| `143103` | 企业单应用消息发送人次 QPM 超限 | 降低发送频率，稍后重试 |
| `143104` | 企业每分钟发送人次 QPM 超限 | 降低发送频率，稍后重试 |
| `143105` | 单应用给单人每日推送量超限 | 控制单人每日消息数量 |
| `143106` | 单应用给单人推送重复消息超限 | 避免一天内反复发送相同内容 |
| `143203` | ISV 单应用发送给单人次 QPM 超限 | 降低发送频率，稍后重试 |
| `143204` | ISV 单应用发送给所有企业人次 QPM 超限 | 降低发送频率，稍后重试 |
| `143205` | ISV 单应用给单人每日推送量超限 | 控制单人每日消息数量 |
| `143206` | ISV 单应用给单人推送重复消息超限 | 避免一天内反复发送相同内容 |


## 四、推荐排查顺序

1. **先检查账号是否绑定钉钉。** 根据接收人的业务账号查询账号信息，确认存在有效的钉钉 `userId`。如果没有绑定，先处理账号绑定问题，无需继续排查钉钉发送链路。
2. **查询消息任务。** 根据消息任务 ID 查询 `status`、`failReason`、`retryCount`、钉钉 `taskId`、接收人和请求报文，确认任务是否进入发送流程。
3. **没有 `taskId` 时排查我方系统。** 依次检查接收人转换结果、消息组装、渠道配置、图片处理、账号中心 RPC、网络和程序异常。
4. **检查钉钉发送接口响应。** 如果钉钉明确返回失败，完整记录 `errcode` 和 `errmsg`，并根据错误信息检查凭证、权限、参数或钉钉服务状态。
5. **有 `taskId` 时查询异步发送结果。** 重点检查 `invalidUserIdList`、`forbiddenList`、`forbiddenUserIdList`、`failedUserIdList` 和 `invalidDeptIdList`。
6. **检查是否触发钉钉发送限制。** 确认是否存在 QPM 超限、单人每日推送量超限或重复消息超限。
7. **区分查询失败和投递失败。** 如果异步结果查询接口本身异常，只能说明结果查询失败，不能直接断定用户没有收到消息。
