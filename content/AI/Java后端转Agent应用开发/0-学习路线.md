# Java 后端转 Agent 应用开发：50 天学习路线

> 更新时间：2026-08-20
>
> 适用对象：已有 Java 后端经验，希望在 50 天内形成 AI 应用开发求职能力。
>
> 最终目标：做出一个可运行、可演示、可写进简历的 Java Agent 项目，并开始投递相关岗位。

## 1. 先确定方向

### 目标岗位

- AI 应用开发工程师
- LLM 应用开发工程师
- Agent 应用开发工程师
- Java AI 应用开发工程师
- 智能客服、企业知识库、AI 办公应用开发工程师

### 核心定位

```text
Java 后端工程师
  + 大模型调用
  + RAG 知识库
  + Tool Calling
  + Agent 工作流
  + 工程化部署
```

不把目标定为大模型算法工程师，暂时不投入模型训练、强化学习和复杂数学推导。

### 50 天内不做的事

- 不系统学习前端
- 不学习模型训练和 PyTorch
- 不同时学习多个 Agent 框架
- 不做第二个项目
- 不追求复杂多 Agent 平台
- 不把时间花在偏门八股和框架源码上

## 2. 固定技术栈

```text
Java + Spring Boot + Spring AI
PostgreSQL + pgvector + Redis
SSE + Docker
RAG + Tool Calling + Agent 工作流
```

### 框架选择

第一选择：Spring AI。重点学习 `ChatClient`、Tool Calling、Vector Store、RAG、Memory 和 MCP。可先阅读 [[3.Spring AI ChatClient]]，再结合 [Spring AI 官方文档](https://docs.spring.io/spring-ai/reference/) 学习。

第二选择：LangChain4j。等第一个项目完成后再了解，不作为 50 天主线。[LangChain4j 官方文档](https://docs.langchain4j.dev/)

### Maven 配置

第 1 天创建项目后，使用 Maven 管理依赖。当前学习项目使用 Java 21、Spring Boot 4.1.1 与 Spring AI 2.0.1；本机 Maven 为 3.9.16，路径为：

```text
/Volumes/data/develop/apache-maven-3.9.16
```

项目未包含 Maven Wrapper 时，可在 IntelliJ IDEA 中将 Maven home 设置为上述路径，或直接使用本机 Maven 执行构建。不要把 API Key 写进 `pom.xml` 或提交到 Git。

基础 `pom.xml` 如下；后续学习 Redis、RAG 等能力时，再按对应章节增补依赖。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <parent>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-parent</artifactId>
        <version>4.1.1</version>
        <relativePath/>
    </parent>

    <groupId>com.afyke</groupId>
    <artifactId>ai-agent-demo</artifactId>
    <version>0.0.1-SNAPSHOT</version>

    <properties>
        <java.version>21</java.version>
        <spring-ai.version>2.0.1</spring-ai.version>
    </properties>

    <dependencyManagement>
        <dependencies>
            <dependency>
                <groupId>org.springframework.ai</groupId>
                <artifactId>spring-ai-bom</artifactId>
                <version>${spring-ai.version}</version>
                <type>pom</type>
                <scope>import</scope>
            </dependency>
        </dependencies>
    </dependencyManagement>

    <dependencies>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-webmvc</artifactId>
        </dependency>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-validation</artifactId>
        </dependency>
        <dependency>
            <groupId>org.springframework.ai</groupId>
            <artifactId>spring-ai-starter-model-openai</artifactId>
        </dependency>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-test</artifactId>
            <scope>test</scope>
        </dependency>
    </dependencies>

    <build>
        <plugins>
            <plugin>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-maven-plugin</artifactId>
            </plugin>
        </plugins>
    </build>
</project>
```

常用命令：

```bash
mvn clean compile
mvn spring-boot:run
```

如果后续同时引入 WebMVC 和 WebFlux，须明确项目的 Web 技术栈；入门阶段默认只保留 WebMVC。Maven 依赖更新后，在 IDEA Maven 面板重新加载项目。

## 3. 每天固定安排

每天 8 小时：

```text
4 小时：Agent 项目开发

```

每天必须留下至少一种成果：

- 可运行代码

- 测试用例

```text

```



## 5. 唯一实战项目

### 项目名称

企业售后与知识库 Agent

### 项目目标

用户可以用自然语言：

- 查询企业制度
- 查询订单状态
- 查询物流信息
- 查询库存
- 创建售后工单

### 最小功能范围

#### 知识库

- 支持 PDF 或 Markdown
- 文档清洗、切片和向量化
- 基于知识库回答问题
- 返回引用文档和段落

#### 业务工具

- 订单查询
- 物流查询
- 库存查询
- 售后工单创建

#### 安全控制

- 用户权限校验
- 文档权限过滤
- 写操作人工确认
- 工具调用审计
- 写操作幂等
- 敏感信息脱敏

### 项目技术栈

```text
Java、Spring Boot、Spring AI
PostgreSQL、pgvector、Redis
SSE、Docker、JWT
```

### 项目最终演示链路

```text
用户提问
  → Agent 判断意图
  → RAG 检索或调用业务工具
  → 后端校验权限
  → 多步骤处理
  → 写操作人工确认
  → 返回结果并保存审计日志
```

## 6. Java 八股复习范围

### 第一优先级

- JVM 内存模型、GC、类加载
- HashMap、ConcurrentHashMap
- 线程池、锁、并发工具
- Spring IOC、AOP、事务
- MySQL 索引、事务、隔离级别、慢查询
- Redis 数据结构、缓存击穿/穿透/雪崩

### 第二优先级

- MQ 可靠性、重复消费、消息丢失
- 分布式锁
- 接口幂等
- 限流、降级、熔断
- 微服务调用和服务治理
- 高并发接口设计

### 面试题回答格式

```text
先说结论
  ↓
解释原理
  ↓
结合项目场景
  ↓
说明异常情况和解决方案
```

不要求 50 天内背完整套八股，优先准备目标岗位最可能问到的内容。

## 7. Agent 面试重点

### RAG

- 为什么使用 RAG，而不是直接把文档放进 Prompt？
- 文档应该如何切片？
- 召回结果不准确如何排查？
- 向量检索和关键词检索如何组合？
- 如何处理文档权限？
- 如何评测 RAG 效果？

### Tool Calling

- Tool Calling 的完整流程是什么？
- 工具参数如何校验？
- 如何防止模型调用没有权限的工具？
- 工具超时和重复调用如何处理？
- 写操作为什么需要人工确认？
- 如何保证工具幂等？

### Agent 工作流

- Agent 和普通聊天接口有什么区别？
- 什么时候使用固定工作流？
- 什么时候让模型自主选择工具？
- 如何限制循环和最大执行步数？
- 多 Agent 是否一定更好？
- 如何保存中间状态和恢复任务？

### 工程化

- 如何控制 Token 成本？
- 如何降低模型调用延迟？
- 如何记录一条完整的 Trace？
- 模型不可用时如何降级？
- 如何做内容安全和敏感数据脱敏？

## 8. 简历项目模板

```text
企业售后与知识库 Agent

技术栈：Java、Spring Boot、Spring AI、PostgreSQL、pgvector、Redis、Docker

1. 基于 Spring AI 搭建企业知识库 Agent，完成 PDF/Markdown 文档解析、切片、Embedding、向量检索和引用返回。
2. 将订单查询、物流查询和售后工单封装为 Tool，实现模型根据用户意图调用 Java 业务接口。
3. 针对创建工单等写操作增加权限校验、幂等控制和人工确认机制，避免模型直接执行高风险操作。
4. 增加会话状态、Prompt 版本、工具调用日志和 RAG 评测集，支持分析回答质量、响应时间和 Token 成本。
5. 使用 Docker 完成服务和数据库部署，并通过 SSE 提供流式对话接口。
```

数字必须使用真实测量结果，不要虚构准确率、性能提升或用户数量。
